Accessible name and description

Assistive technologies expose an accessible name (and optionally a description) computed from the DOM — not from what merely looks like a label. Prefer visible text and native associations; use ARIA when you cannot.

Naming interactive content

For many controls, the accessible name comes from the text content inside the element — including nested elements. That name stays visible to everyone. aria-label can override it for assistive technologies only.

Icon buttons — ways to name

Icon-only controls need an accessible name. You can supply it with visually hidden text, ARIA, an image alt, or an SVG <title>. Prefer a visible text label when space allows.

Naming form inputs

Prefer a visible <label> (wrapping or for/id). aria-label and aria-labelledby work, but leave sighted users without a visible label unless you add one separately.

Images: alt vs ARIA

When an image fails to load, browsers show alt as visible fallback text. aria-label / aria-labelledby still name the image for assistive technologies, but nothing appears on screen — so sighted users see a broken image with no explanation.
