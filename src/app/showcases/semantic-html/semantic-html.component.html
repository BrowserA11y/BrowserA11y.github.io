Semantic HTML

Assistive technologies expose the accessibility tree, not your CSS. Choosing the right elements — and putting required children in the right place — determines what screen readers announce and how people navigate.

Price changes with del and ins

Use del and ins for removed and inserted content (for example a sale price). Styling a generic element to look struck-through does not convey deletion. Prefer real semantics over <s> or visual-only spans — see s vs del in HTML.

fieldset needs legend first

The rule for you: The legend element must be the first child. If it isn't, the code is technically non-conforming and will fail an official HTML validator (see the legend element). The rule for the browser: The standard tells browser engines to look inside the fieldset and use the first legend element they encounter, regardless of what elements sit in front of it (see WHATWG HTML #6645).

table needs caption first

For authors, caption must be the first child of table — anything else is invalid HTML (see the caption element in the WHATWG HTML Standard). Angular can keep a caption at the wrong position in the DOM, because Angular's templates are built with DOM APIs and bypass the HTML stream parser. Chrome does not fix that in the Elements panel; Blink’s accessibility code builds a separate tree and adds the caption first via AXNodeObject::AddTableChildren(), and still uses it for the table’s accessible name. Treat that as browser recovery, not a reason to ship misplaced captions.
