Color contrast and use of color

WCAG asks for enough luminance contrast so text and meaningful UI cues stay readable, and for meaning that does not depend on hue alone. Compare passing and failing pairs below — ratios are against a white page background.

Normal text — 4.5:1

Body-size text needs at least a 4.5:1 contrast ratio against its background (WCAG 1.4.3 Contrast Minimum).

Passes (7:1)

Shelf hours update every Monday. Check the notice board before you visit.

Fails (3:1)

Shelf hours update every Monday. Check the notice board before you visit.

Larger or bold text — 3:1

Larger text (18pt / 24px) or bold text (14pt / 18.5px) only needs 3:1. The samples below use bold 1.25rem type. The passing sample reuses the 3:1 gray from the normal-text failure above.

Non-text contrast — 3:1

Visual information needed to identify controls and states must contrast at least 3:1 with adjacent colors (WCAG 1.4.11). Patterns below follow the Understanding doc examples for borders, button fills, and selection.

Input border — passes

Border #767676 (4.5:1) against white — enough to see the field.

Input border — fails

Border #D0D0D0 (1.5:1) — the field is easy to miss.

Button — passes

Button fill #114446 against white (10:1) — the control is easy to identify.

Button — fails

Button fill #E8F0EE against white (1.2:1) — the control barely stands out from the page.

Selected state — passes

Selected option uses a light check mark (15:1 on the button), not hue alone.

Selected state — fails

Selected option uses a yellow outline (1.1:1 on white) — visible but insufficient non-text contrast.

Use of color

Do not convey information with color alone (WCAG 1.4.1). Pair hue with text, shape, pattern, or another non-color cue.

Status dots — passes

  • Available
  • On hold
  • Overdue

Color plus visible text labels.

Status dots — fails

  • Available
  • On hold
  • Overdue

Sighted users only get colored dots — meaning is lost without color perception. (Screen readers still hear the hidden labels.)

Palette icon-buttons — passes

Color fills the button with a visible name; pressed state uses outline.

Palette icon-buttons — fails

Only colored fills distinguish options for sighted users.
