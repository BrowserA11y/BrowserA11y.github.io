High contrast mode

Windows High Contrast (and similar “forced colors” modes) replace many author colors with a limited system palette. Detect that with forced-colors: active or Angular CDK’s cdk.high-contrast() mixin, then restyle with currentColor or CSS system colors — not brand hex values. Emulate in DevTools: Rendering → Emulate CSS media feature forced-colors: active.

Colored text, links, and a button

Author colors look fine in the default theme. With forced colors on, the browser remaps color, backgrounds, and borders to system colors so contrast stays usable.

SVG fill options

fill is forced in high contrast mode. Hardcoded brand colors do not survive. Prefer currentColor (follows the parent’s forced text color) or a system color that matches the control context.

fill: #c45c26

Author brand fill — ignored when forced colors are active.

fill: currentColor

Tracks the element’s color (usually CanvasText once forced).

System colors

  • CanvasText
  • LinkText

Also useful: ButtonFace, ButtonBorder, GrayText, Highlight / HighlightText, VisitedText, ActiveText.

Override that works

Default brand fill would vanish in forced colors. Inside cdk.high-contrast() (or @media (forced-colors: active)), set fill: currentColor so the icon matches surrounding text.

Featured collection

SCSS: @include cdk.high-contrast() { fill: currentColor; }

forced-color-adjust: none

Opt out of the UA color remap when you must keep author colors — for example a brand swatch or a chart. You become responsible for contrast. Prefer adapting with system colors or currentColor when you can.

Keep author colors

forced-color-adjust: none — dark blue text and orange fill stay as authored even when forced colors are active.

CDK outline on a button

Default box-shadow is forced to none. @include cdk.high-contrast() { outline: solid 1px; } restores a visible edge.
